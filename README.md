# Óleńsiz

**[olensiz.zhengisbay.com](https://olensiz.zhengisbay.com)**

Угадай казахскую песню по короткому фрагменту.
Статичный сайт на казахском и русском, без бэкенда и без единой зависимости.

Хостинг — GitHub Pages, домен — Cloudflare DNS.
Деплой: любой пуш в `main` публикуется автоматически.
Старый адрес `songless.zhengisbay.com` отдаёт 301 на новый и не удалён —
он проиндексирован, и редирект передаёт вес.

```bash
npm start          # → http://localhost:5173   игра
npm run editor     # → http://localhost:5175   редактор каталога (локально)
```

Node 18+. `npm install` не нужен: зависимостей нет.
Десктоп, база 1440×900. Тема тёмная. Ни один экран не скроллится.

## Что это

Партия — пять раундов, каждый на ступень сложнее предыдущего:
**Оңай → Орташа → Қиын → Өте қиын → Аңыз**.

Внутри раунда — несколько ступеней прослушивания. Их длина зависит от режима:

| Режим | Ступени | Очки |
| --- | --- | --- |
| **Қарапайым** (обычный) | 2 → 4 → 6 → 10 → 14 → 20 с | ×1,0 |
| **Сарапшы** (экспертный) | 0,1 → 0,5 → 1 → 2 → 4 → 8 → 16 с | ×1,8 |

Экспертный режим не просто короче: на верхних уровнях он подмешивает редких
исполнителей и андеграунд. Множитель — плата за реальную сложность, а не за
скорость реакции.

Чем раньше узнал, тем больше очков; и «Өткізу», и неверный ответ открывают
следующую ступень. Выбранный вариант проверяется только по кнопке **«Тексеру»** —
до нажатия его можно поменять.

Проигрыша нет. Раунд в любом случае заканчивается карточкой с обложкой,
названием, именем артиста и ссылками на стриминги. Финал показывает все пять
карточек разом — на каждой видно, на каком шаге ты ответил, за сколько и сколько
это принесло, — и даёт emoji-сетку для шеринга.

**661 трек, 130 исполнителей, 9 категорий** — от Ninety One и Скриптонита до
Дос-Мұқасан и Роза Рымбаевой.

## Каталог: почему в нём не может быть чужой песни

Каталог собирается **строго по whitelist артистов** из
[`data/artists-v2.csv`](data/artists-v2.csv):

1. Имя артиста из CSV → `artistId` через `entity=musicArtist`.
2. Треки — **только** через `lookup?id={artistId}&entity=song`.
3. Каждый трек ещё раз сверяется с whitelist по `artistId`.

Свободного текстового поиска по названиям в сборщике нет вообще. Это
архитектурная гарантия, а не фильтр: списка названий, по которым можно было бы
случайно вытащить чужое, просто не существует.

Одного whitelist по ID оказалось мало — односложные имена делят с чужими людьми
по всему миру (`Junior` — испанский исполнитель, `Duman` — турецкая рок-группа,
`ZAQ` — японская, `Ali` — панджабский). Поэтому добавлено разрешение
однофамильцев: артист принимается, только если у него есть попадания в
названия песен из колонки `notes` или заметная доля кириллицы. Не подтвердился —
не попадает в каталог и уходит в отчёт `data/build-report.md`.

В третьей итерации нашлась ещё одна дыра: под «Ириной Кайратовной» оказался
англоязычный трек чужого исполнителя. Причина — алиас `IK` длиной в две буквы:
такие совпадают с кем угодно. Теперь **алиасы короче четырёх символов не
участвуют в опознании артиста** (только в поиске игрока), а каждое слияние
нескольких профилей одного артиста выписывается в отчёт сборки отдельной
таблицей — ошибочное будет видно там, а не в игре.

**Категории.** Тонкие жанры слиты в родительские (`jazz`→`rnb`,
`electronic`→`pop`, `classical`→`pop`), а категория, в которой меньше 25 треков,
не показывается в фильтрах вовсе: пустая категория обманывает игрока сильнее,
чем её отсутствие. Исходные теги при этом сохраняются в поле `tags` каждого
трека. Таблица «категория → треков → показывается» есть в отчёте сборки.

**Без повторов.** Сыгранные треки запоминаются в `localStorage`; пока каталог
не исчерпан, один и тот же трек второй раз не выпадет. Когда свободных треков
не остаётся в каком-то уровне, история сбрасывается только для него.

```bash
npm run build:catalog     # пересобрать (кэш в .cache/, повторный запуск мгновенный)
```

Отчёт сборки: сколько обработано, кто отвалился и почему, кто отклонён как
неподтверждённый, список `needs_review`.

## Поиск прощает орфографию

Игра проверяет слух, а не умение писать.

| Наберёте | Найдёт |
| --- | --- |
| `кара бала` | Qara Bala |
| `қара бала` | Qara Bala |
| `karabala` | Qara Bala |
| `Сени суйем` | Сені сүйем |
| `Акку` | Аққу |
| `katadan` (с опечаткой) | Қайтадан |

Двойная нормализация: `қ↔k`, `ә↔a`, `ө↔o`, `ү/ұ↔u`, `ң↔n`, `ғ↔g`, `і↔i`,
`j↔zh`, `y↔i`, латиница ↔ кириллица, плюс Левенштейн ≤2 и триграммная близость.
Реализация — [`src/normalize.js`](src/normalize.js) и
[`src/catalog.js`](src/catalog.js), регрессия — `npm run verify:search`.

Список вариантов намеренно показывает похожие треки: перепутать «Аяулым» трёх
разных исполнителей — часть механики.

## Загрузка и звук

**Все пять треков раунда декодируются до старта партии.** Партия не начинается,
пока не готовы все пять; идёт прогресс загрузки. Не загрузившийся за таймаут
трек молча подменяется запасным того же уровня.

Замер: пять треков ≈ 3,4 секунды, нажатие «Ойнату» стартует звук за ~70 мс.

**Детектор тишины.** Превью от API — вырезка из середины трека, и начинаться она
может с тишины. RMS окнами по 10 мс ищет первый момент, где уровень стабильно
(≥50 мс подряд) выше −40 dBFS; все ступени отсчитываются оттуда. Плюс эвристика
райзера: если начало заметно глуше остального превью того же трека, точка
сдвигается к первому перкуссионному онсету. Результат кэшируется в
`localStorage`. Посмотреть, что нашёл детектор: `?debug=1`.

## Фон, который живёт под музыку

Когда угаданный трек играет, из его обложки извлекаются доминирующие цвета
(canvas + квантизация, без библиотек) — и фон приходит в движение двумя
независимыми способами.

**Течение.** Три цветных пятна плывут по своим траекториям с разными периодами
(19/23/29 секунд — взаимно простые, поэтому картинка не зацикливается на глаз).
Это чистый CSS на transform: движение идёт на композиторе и не зависит от того,
играет ли музыка. В тишине фон тоже живой.

**Реакция на бит.** Энергия полосы 20–200 Гц из `AnalyserNode`: на пике картинка
светлеет к белому, чуть расширяется и получает мягкое свечение. Против
стробоскопа стоят три ограничителя — сглаживание самого анализатора,
асимметричное сглаживание (быстрая атака, медленный спад: бит «повисает») и
жёсткий потолок изменения за кадр.

Между фоном и контентом лежит вуаль: она темнее всего там, где живёт текст, и
растворяется к краям. Без неё подпись альбома на зелёном пятне переставала
читаться. При `prefers-reduced-motion` не работает ни движение, ни пульсация —
остаётся ровный градиент.

## Очки

```
bonus = S_k · 0.25 · exp( −max(0, t − 0.35) / 6 )        ≥ 0, ≤ 25% ступени
раунд = round( max(S_k + bonus, 0.10 · S_k) · M )        M = 1.0 или 1.8
```

Три правила, ради которых формула переписана в третьей итерации:

1. **Бонус только добавляет.** Он не бывает отрицательным и не может уменьшить
   базу ступени. Скорость может очков не дать — отобрать не может.
2. **Верный ответ никогда не стоит нуля.** Узнать песню с 16 секунд — это тоже
   узнать. Ноль означает ровно одно: трек не угадан.
3. **Ступень всегда важнее скорости.** Ответ на ступени `k` без бонуса обязан
   обойти ответ на `k+1` с максимальным бонусом; отсюда математически выведен
   потолок бонуса.

Бонус считается от **времени до первого нажатия**, а не до отправки ответа:
длина названий и скорость печати у всех разные, а момент «понял» — универсален.
Из него вычтен физиологический пол реакции 0,35 с.

Цену ступени игра больше не показывает числом: настоящий результат зависит ещё
от времени и режима, и цифра с итогом не сходилась. Вместо неё — убывающий
столбик.

Проверяется автоматически: `npm run verify:scoring`.
Полный вывод формулы, примеры расчёта и разбор способов накрутки —
в [SCORING.md](SCORING.md).

## Ноль скроллинга

Жёсткое требование: каждый экран помещается в один вьюпорт.

- `html, body { overflow: hidden }`, оболочка на `100dvh`;
- все размеры — `clamp()` от высоты вьюпорта;
- **деградация по высоте** ([`src/fit.js`](src/fit.js)): JS-наблюдатель ставит
  `data-dense` 0..4, CSS по нему прячет второстепенное — декор → счётчик
  уровней → подписи → второй лидерборд;
- выпадающая выдача поиска сама выбирает направление и высоту по свободному
  месту, чтобы не закрывать плеер и не обрезаться краем экрана.

Никогда не прячутся: кнопка воспроизведения, поле поиска, кнопка действия
(«Өткізу» / «Тексеру»), текущий счёт, индикатор ступени.

```bash
npm run verify:noscroll
```

Гоняет headless Chrome по всем экранам на шести высотах (1080…520) и проверяет
оба условия. Скролл разрешён ровно в двух местах: полный список лидеров в
оверлее и аварийный сценарий при высоте < 480px.

## Редактор каталога (локально)

```bash
npm run editor     # → http://localhost:5175
```

Отдельная страница только для владельца проекта. **Не деплоится и в продакшене
не работает** — сохранять ей некуда без локального сервера.

Что в ней есть: таблица всех треков с обложками, встроенный плеер, **волна
превью с перетаскиваемой точкой старта** (решает проблему треков, начинающихся
с тишины), ползунок уровня 1–5, редактируемые категории, возрастной рейтинг,
заметка и кнопка «скрыть из игры». Поиск и фильтры, включая «только
непроверенные» и «только с флагами».

Правила слияния, ради которых это сделано именно так:

- каждое поле показывает **текущее** значение и откуда оно — `авто` из сборки
  или `моё` из `data/overrides.json`;
- в файл пишутся **только реально изменённые поля**; ничего не трогал —
  записи нет;
- **пересборка каталога никогда не затирает правки**: сборщик накладывает
  `overrides.json` последним;
- прогресс «проверено N из 661» всегда на виду.

Почему сервер, а не `localStorage`: правки должны переживать перезапуск и быть
видны сборщику каталога, а браузерное хранилище он прочитать не может.
Сервер принимает запросы только с 127.0.0.1 и записывает только известные поля —
он пишет в репозиторий.

### Проверки

```bash
npm run verify            # очки, поиск и каталог, контраст
npm run verify:noscroll   # отдельно: требует поднятого сервера и Chrome
```

- **очки** — инвариант доминирования ступени, нелинейность убывания,
  отсутствие отрицательных значений при любых входах;
- **поиск и каталог** — казахская орфография, опечатки, канонический сценарий
  «кара бала» → «Qara Bala»; уровни из тиров, фильтры, защита от пустой выборки,
  отсутствие запрещённых артистов, объём каталога;
- **контраст** — все пары цветов по WCAG, плюс проверка, что следов светлой
  темы не осталось;
- **скролл** — все экраны на шести высотах вьюпорта.

## Оформление

Swiss / International Typographic: строгая сетка, сильная типографика, много
воздуха, ноль декора. Никакого орнамента — современно, а не сувенирно.

Один акцентный цвет, вся остальная шкала нейтральная и намеренно бесцветная,
**чтобы обложки альбомов оставались единственным крупным цветовым пятном** —
и чтобы динамический фон, окрашенный обложкой, читался как событие.

Контраст: основной текст ≥ 7:1 (AAA), вторичный и акцент ≥ 4.5:1, границы
контролов ≥ 3:1. Вся игра проходится с клавиатуры, `prefers-reduced-motion`
отключает 3D, параллакс и пульсацию.

> **Референс стиля не задавался.** В задании поле `РЕФЕРЕНС:` осталось пустым,
> поэтому визуальный язык не менялся и `STYLE_REFERENCE.md` не создавался.

## Правовая заметка

Игра использует **официальные публичные превью-API**:
[iTunes Search API](https://performance-partners.apple.com/search-api) отдаёт
метаданные и ссылки на 30-секундные превью, которые Apple публикует открыто.

**Аудиофайлы не хранятся и не скачиваются.** В репозитории нет ни одного mp3
или m4a. `data/tracks.json` содержит только метаданные и URL превью; звук
загружается в браузере игрока напрямую с CDN Apple при воспроизведении.

**Каждый трек атрибутирован исполнителю.** Имя артиста показывается на карточке
результата каждого раунда и на каждой карточке финального экрана — без
исключений, это не опция оформления. Рядом всегда стоят ссылки на
**Apple Music** (точная ссылка из API), **Spotify** и **Deezer** (поисковые),
чтобы игрок мог послушать песню целиком у правообладателя. Карточка финала
открывается кликом и показывает те же ссылки.

Обложки альбомов отображаются по ссылкам на CDN Apple в том виде, в каком их
публикует API, и не копируются в проект. Извлечение цветов происходит в браузере
игрока и никуда не сохраняется.

Проект некоммерческий и образовательно-развлекательный. Если вы правообладатель
и хотите убрать свой трек — удалите строку артиста из `data/artists-v2.csv`
и пересоберите каталог, либо скройте конкретный трек в локальном редакторе.
