# SETUP.md — установка, лидерборды, деплой

---

## 1. Запуск локально

Нужен только Node 18+. Зависимостей у проекта нет, `npm install` делать не надо.

```bash
npm start
```

Откроется `http://localhost:5173`. Команда сначала прогоняет проверку
инвариантов системы очков, потом поднимает статический сервер.

| Команда | Что делает |
| --- | --- |
| `npm start` | Проверка очков + сервер |
| `npm run dev` | Только сервер |
| `npm run verify` | Очки, поиск и каталог, контраст токенов |
| `npm run verify:noscroll` | Проверка «ноль скроллинга» в headless Chrome |
| `npm run build:catalog` | Пересобрать `data/tracks.json` (использует кэш `.cache/`) |
| `npm run build:catalog:fresh` | То же, но игнорируя кэш — ходит в сеть заново |
| `npm run screenshots` | Скриншоты экранов в `.design/tap-anda/screenshots/` |
| `npm run og` | Пересобрать `og-image.png` 1200×630 |
| `npm run editor` | Локальный редактор каталога → `http://localhost:5175` |
| `http://localhost:5173/?debug=1` | В консоль пишутся найденные `startOffset` |

> Сервер нужен только потому, что ES-модули и `fetch` не работают по `file://`.
> Сборки нет: то, что лежит в папке, — это и есть готовый сайт.

**Игра рассчитана на десктоп** (база 1440×900). Мобильной версии нет
сознательно — это отдельный проект.

## 2. Лидерборды через Google Sheets

Лидерборды **необязательны**. Пока `LEADERBOARD_ENDPOINT` пуст, игра работает
полностью: правая колонка стартового экрана просто не показывается, форма
отправки на финале скрыта, и **ни одного сетевого запроса к таблице не уходит**.
Если они вам не нужны — раздел можно пропустить.

На стартовом экране два топа: **Барлық уақыт** (за всё время) и **Бүгін**
(сегодня). Оба приходят одним запросом.

### Шаг 1. Создать таблицу

1. Откройте [sheets.new](https://sheets.new) — создастся пустая таблица.
2. Назовите её как угодно, например **ТАП ӘНДІ — рекорды**.
3. Лист создавать вручную не нужно: скрипт сам заведёт лист `scores`
   с заголовками при первой записи.

### Шаг 2. Вставить скрипт

1. В таблице: меню **Расширения → Apps Script** (Extensions → Apps Script).
2. Откроется редактор с файлом `Код.gs` (`Code.gs`) и заготовкой `myFunction`.
3. **Удалите всё содержимое** этого файла.
4. Откройте [`scripts/apps-script.gs`](scripts/apps-script.gs) из репозитория,
   скопируйте целиком и вставьте в редактор.
5. Нажмите значок дискеты (**Сохранить проект**).

Настройки в начале файла при желании меняются:

```js
var SHEET_NAME = 'scores';            // имя листа
var DEFAULT_TOP = 7;                  // строк в каждом топе
var TIMEZONE = 'Asia/Almaty';         // по какому поясу считается «сегодня»
var RATE_LIMIT_SECONDS = 20;          // не чаще одной отправки в 20 секунд
var ONE_SUBMIT_PER_SESSION = true;    // одна запись на сессию браузера
```

`MAX_GAME_SCORE` и `MAX_ROUND_SCORE` трогать не надо — они должны совпадать
с константами в `src/scoring.js`, иначе валидация начнёт врать.

### Шаг 3. Проверить, что скрипт живой

1. В выпадающем списке функций сверху выберите **`testEndpoints`**.
2. Нажмите **Выполнить** (Run).
3. Google попросит разрешения — это нормально, скрипт пишет в вашу же таблицу:
   - **Разрешить доступ** → выберите свой аккаунт;
   - экран «Google не подтвердил это приложение» → **Дополнительные настройки**
     → **Перейти на страницу «...» (небезопасно)**;
   - **Разрешить**.
4. Внизу откроется **Журнал выполнения**. Ожидаемо увидеть пять строк:

   | Строка | Что должно быть |
   | --- | --- |
   | `честный:` | `{"ok":true,"rank":1}` — запись прошла |
   | `топы:` | `{"ok":true,"allTime":[...],"today":[...]}` — оба топа читаются |
   | `накрутка:` | `{"ok":false,"error":"impossible-score"}` — **счёт выше максимума отбит** |
   | `мат в нике:` | `{"ok":false,"error":"nick-bad"}` — **фильтр мата работает** |
   | `sum-mismatch:` | `{"ok":false,"error":"sum-mismatch"}` — **несходящаяся сумма отбита** |

   Если последних трёх строк нет — валидация не работает, проверьте, что
   вставили файл целиком.
5. Вернитесь в таблицу: появился лист `scores` с тестовой строкой. Её можно
   удалить, заголовки трогать не надо.

### Шаг 4. Опубликовать как веб-приложение

1. В редакторе: **Начать развёртывание** (Deploy) → **Новое развёртывание**.
2. Слева от «Выберите тип» нажмите шестерёнку → **Веб-приложение** (Web app).
3. Заполните:
   - **Описание**: `tap-anda leaderboard v2` (любое);
   - **Запуск от имени** (Execute as): **Я** (`Me`) — иначе у скрипта не будет
     доступа к таблице;
   - **У кого есть доступ** (Who has access): **Все** (`Anyone`).
     > Обязательно. `Anyone with Google account` не подойдёт: игроки не
     > авторизуются, и запросы будут получать 401.
4. **Развернуть** (Deploy) → при необходимости ещё раз выдайте разрешения.
5. Скопируйте **URL веб-приложения**:

   ```
   https://script.google.com/macros/s/AKfycb................/exec
   ```

   Адрес должен заканчиваться на **`/exec`**, а не на `/dev`.
   `/dev` работает только для вас и игрокам недоступен.

### Шаг 5. Вписать URL в игру

Откройте [`src/config.js`](src/config.js):

```js
export const CONFIG = {
  LEADERBOARD_ENDPOINT: 'https://script.google.com/macros/s/AKfycb.../exec',
  ...
};
```

Перезагрузите страницу. Справа на стартовом экране появятся два топа, на
финальном — поле ника и кнопка отправки.

### Шаг 6. Проверить в браузере

Откройте URL веб-приложения прямо в адресной строке:

```
https://script.google.com/macros/s/.../exec?action=top&limit=5
```

Должен вернуться JSON `{"ok":true,"allTime":[...],"today":[...]}`. Если вместо
него страница входа в Google — на шаге 4 не выбран доступ «Все».

### Обновление скрипта после правок

Правки в редакторе **не публикуются автоматически**. После каждого изменения:
**Начать развёртывание → Управление развёртываниями → карандаш → Версия:
Новая версия → Развернуть**. URL сохраняется.

### Что именно проверяет сервер

Клиентская проверка бесполезна против намеренного читера — он правит клиент.
Поэтому всё важное проверяется в Apps Script:

| Проверка | Код отказа |
| --- | --- |
| Счёт — целое в диапазоне 0…11250 | `impossible-score`, `bad-score`, `negative-score` |
| Ровно 5 раундов | `bad-rounds` |
| Очки раунда — целое 0…2250 | `impossible-round`, `bad-round-points` |
| Номер ступени 1…7 | `bad-step` |
| Очки раунда не выше потолка своей ступени **в своём режиме** | `round-exceeds-step-cap` |
| Непойманный раунд обязан быть нулевым | `unsolved-with-points` |
| Сумма раундов равна общему счёту | `sum-mismatch` |
| Одна запись на сессию / не чаще 1 раза в 20 с | `already-submitted`, `rate-limited` |
| Ник ≥ 2 символов, либо пустой (тогда игрок станет `Qonaq N`) | `nick-too-short` |
| Мат в нике (с учётом `b1tch`, `$hit`) | `nick-bad` |
| Ведущие `= + - @` в нике срезаны | *(formula injection в Sheets)* |
| Срез приводится к безопасному виду, произвольная строка не проходит | *(колонка `slice`)* |

### Срезы (важно при чтении таблицы руками)

Результаты пишутся в колонку `slice` в виде `категория|режим|возраст`,
например `random|expert|family`. Таблица считается по срезам, потому что
экспертный режим даёт очков в 1,8 раза больше и общий список сравнивал бы
несравнимое. Строки, записанные до появления срезов, при чтении считаются
`random|normal|family` — иначе они бы просто исчезли.

Имя игрока необязательно: если поле пустое, сервер сам присваивает
`Qonaq 1`, `Qonaq 2` и так далее, просматривая уже занятые номера.

**Чего это не закрывает.** Игрок с открытыми DevTools может подменить счёт на
любое значение внутри допустимого диапазона, и отличить его от честного
результата статичный сайт не может ничем. Это игра, а не банк. Появится
подозрительная строка — удалите её вручную, при чтении скрипт мусорные строки
пропускает.

### Что видно игроку, а что нет

Короткий ответ на вопрос «раз сайт статичный, не утечёт ли таблица»: **нет,
при этой схеме — не утечёт**, и вот почему.

В коде сайта лежит **только адрес веб-приложения** (`.../exec`). Ключей,
паролей и токенов нет вообще. Сам скрипт исполняется на серверах Google от
вашего имени, и он умеет ровно две вещи: принять результат партии и отдать
топ-N строк. Ни файла таблицы, ни доступа к вашему Google-аккаунту адрес не
даёт: по нему нельзя ни прочитать таблицу целиком, ни что-то в ней удалить,
ни добраться до других ваших файлов.

Чего действительно нельзя делать никогда — это класть в репозиторий **JSON-ключ
сервисного аккаунта или API-ключ Google с правом записи в Sheets**. Вот тогда
всё было бы ровно так, как вы опасаетесь: ключ лежит в исходнике, открывается
через «Просмотр кода страницы», и с ним чужой человек делает с таблицей что
захочет. Именно поэтому здесь и выбран Apps Script.

Что при статичном сайте объективно возможно, и не лечится ничем: любой может
отправить на этот адрес выдуманный результат — своими руками через консоль.
Против этого на сервере стоит потолок очков, проверка суммы по раундам,
ограничение частоты и одна запись на сессию; остальное — ваша модерация.
Это игра, а не банк.

Если однажды захочется уйти с Google, схема «статичный сайт + чужой сервер»
сохраняется с любым бесплатным бессрочным хранилищем, у которого есть
HTTP-эндпоинт (Cloudflare Workers + KV, Supabase, Firebase). Менять придётся
только `src/leaderboard.js` — остальная игра о лидерборде ничего не знает.

### Модерация: как убрать чужое имя

Таблица — источник правды, и правится она руками. Удалили строку в Google
Sheets — она пропадает у всех игроков при следующей загрузке страницы:
лидерборд запрашивается заново на каждом заходе на стартовый экран, с
`cache: no-store` и уникальным параметром запроса, поэтому ни браузер, ни
кэширующий фронт Google не покажут удалённое.

Фильтр мата стоит на обеих сторонах (`src/leaderboard.js` и `apps-script.gs`),
но он грубый и всего не поймает. Список корней лежит в начале обоих файлов —
дополнять его можно прямо там; серверный список важнее, клиентскому доверять
нельзя.

## 3. Деплой — как всё устроено сейчас

Сайт опубликован: **https://olensiz.zhengisbay.com**
Старый адрес **songless.zhengisbay.com** отдаёт 301 на новый.

| Что | Где |
| --- | --- |
| Репозиторий | `norawly/songless` (публичный; имя репозитория осталось прежним) |
| Хостинг | GitHub Pages, ветка `main`, каталог `/` |
| Домен | Cloudflare, зона `zhengisbay.com` |
| DNS: новый адрес | `CNAME olensiz → norawly.github.io`, **DNS only (серое облако)** |
| DNS: старый адрес | `CNAME songless → olensiz.zhengisbay.com`, **Proxied (оранжевое)** |
| Редирект | Rules → Redirect Rules → «songless… → olensiz…», 301, путь и query сохраняются |
| TLS | сертификат GitHub Pages, HTTPS принудительный |

### Почему два поддомена настроены по-разному

Это не небрежность, а следствие двух несовместимых требований.

**`olensiz` без прокси**, потому что GitHub Pages продлевает TLS-сертификат
проверкой HTTP-01, а прокси Cloudflare её перехватывает: через 90 дней
сертификат не продлился бы и сайт перестал бы открываться по HTTPS.

**`songless` под прокси**, потому что иначе Cloudflare не увидит запрос и не
сможет отдать 301. GitHub Pages обслуживает ровно один кастомный домен, так что
сам он редирект отдать не может. Под прокси запрос до GitHub вообще не доходит:
Redirect Rule срабатывает на границе Cloudflare.

**Публикация новой версии — это просто пуш:**

```bash
git add -A && git commit -m "что изменилось" && git push
```

Через минуту-две изменения на сайте. Ничего собирать не нужно: репозиторий и
есть сайт.

### Если захочется включить прокси и для основного домена

Тогда TLS должен терминировать Cloudflare: режим SSL/TLS → **Full**, и
полагаться придётся на сертификат Cloudflare, а не GitHub. Это даст CDN,
аналитику и защиту от DDoS. Сейчас в этом нет нужды — GitHub Pages сам по себе
на CDN, — поэтому оставлено проще и надёжнее.

### Проверить, что всё живо

```bash
curl -sI https://olensiz.zhengisbay.com/            # 200
curl -sI https://songless.zhengisbay.com/about.html # 301 + location с тем же путём
```

### Файлы, от которых зависит публикация

- `CNAME` — в нём домен (`olensiz.zhengisbay.com`). Удалите его, и Pages
  отвяжет домен.
- `.nojekyll` — отключает обработку Jekyll, чтобы Pages отдавал файлы как есть.
- `sitemap.xml`, `robots.txt` — SEO; при смене домена обновить оба.

### Другие площадки

Если понадобится перенести: сайт статический, собирать нечего.
Netlify — перетащить папку на [app.netlify.com/drop](https://app.netlify.com/drop);
Vercel / Cloudflare Pages — framework preset **Other**, build command пустой,
output directory — корень.

## 4. Обновление каталога песен

Каталог собирается **строго по whitelist артистов** из
[`data/artists-v2.csv`](data/artists-v2.csv). Свободного поиска по названиям треков
в сборщике нет — именно поэтому чужая песня в каталог попасть не может.

1. Отредактируйте `data/artists.csv`:

   | Колонка | Зачем |
   | --- | --- |
   | `artist`, `aliases` | по ним ищется `artistId` |
   | `fame_tier` 1..5 | определяет уровень сложности и сколько треков взять (10/7/5/3/2) |
   | `genres` | жанровые фильтры на старте |
   | `age` | `family` или `18plus` |
   | `kz_origin` | `verify` помечает треки флагом `needsReview` |
   | **`notes`** | **важнее, чем кажется**: названия песен отсюда используются и для ранжирования «топ-N», и для опознания артиста среди однофамильцев |

2. Пересоберите:

   ```bash
   npm run build:catalog
   ```

   Ответы API кэшируются в `.cache/`, поэтому повторные запуски мгновенны.
   Чтобы сходить в сеть заново — `npm run build:catalog:fresh` (~5 минут).

3. Прочитайте отчёт **`data/build-report.md`**. В нём:
   - сколько артистов обработано и сколько треков собрано;
   - **кто отвалился и почему**;
   - **кто отклонён как неподтверждённый** — это защита от однофамильцев;
   - список `needs_review` (`kz_origin=verify`) для ручной проверки;
   - сколько треков отсеяно каждым фильтром.

4. Проверьте и закоммитьте:

   ```bash
   npm run verify:search
   ```

**Если ваш артист попал в «Отклонены как неподтверждённые»** — значит, у него
нет ни кириллицы в названиях, ни совпадений с колонкой `notes`, и отличить его
от иностранного однофамильца нельзя. Впишите в `notes` название любой его
реальной песни и пересоберите: одной строки достаточно.

**Аудиофайлы не скачиваются никогда.** В JSON попадают только метаданные и
ссылка на 30-секундное превью на CDN Apple.

## 5. Диагностика

| Симптом | Причина и что делать |
| --- | --- |
| Белый экран, в консоли `каталог HTTP 404` | Открыли `index.html` как файл. Нужен `npm start`: по `file://` `fetch` не работает. |
| «Ән тізімі жүктелмеді» | Нет сети или отсутствует `data/tracks.json`. Соберите каталог. |
| Партия долго не стартует | Идёт предзагрузка пяти треков — так и задумано, партия не начнётся, пока все не готовы. Обычно 3–5 секунд. |
| «Дыбыс ойналмады» на каждом треке | Заблокированы запросы к `audio-ssl.itunes.apple.com` (блокировщик, корпоративный прокси). |
| Фон не окрашивается под музыку | Заблокирован `is1-ssl.mzstatic.com` либо включён `prefers-reduced-motion` (тогда градиент статичный — это норма). |
| Кнопка «Бастау» неактивна | Фильтры дают меньше треков, чем нужно на 5 уровней. Сообщение под кнопкой объясняет; ослабьте фильтр или нажмите «Кездейсоқ». |
| Экран всё-таки скроллится | Высота вьюпорта меньше 480px — это единственный разрешённый аварийный случай. Проверить всё остальное: `npm run verify:noscroll`. |
| Лидерборды не появляются | `LEADERBOARD_ENDPOINT` пуст (так и задумано) либо URL заканчивается на `/dev` вместо `/exec`. |
| Отправка даёт `already-submitted` | Одна запись на сессию. Перезагрузите вкладку или поставьте `ONE_SUBMIT_PER_SESSION = false`. |
| Отправка даёт `sum-mismatch` | Константы очков в `apps-script.gs` разошлись с `src/scoring.js`. Синхронизируйте. |
| Интерфейс на русском при первом заходе | Выбор языка сохранён в `localStorage`. Очистите его — игра всегда стартует на казахском. |

## 6. Локальный редактор каталога

```bash
npm run editor        # → http://localhost:5175
```

Страница только для владельца проекта: **в продакшн она не попадает и без
локального сервера не работает** — сохранять ей некуда. Путь `/scripts/`
закрыт в `robots.txt`.

Что можно поправить у каждого трека: точку старта (перетаскиванием прямо по
волне превью, с немедленным прослушиванием), уровень сложности 1–5,
категории, возрастной рейтинг, заметку; трек можно скрыть из игры совсем.

Правки пишутся в `data/overrides.json` и **не теряются при пересборке**:
сборщик каталога накладывает их последними. В файл попадают только реально
изменённые поля — ничего не трогали, записи нет.

```json
{
  "1234567890": { "startOffset": 3.42, "tier": 2, "age": "18plus" }
}
```

Отдельной кнопки «Сохранить» нет намеренно: каждая правка пишется в файл в тот
же момент, когда её сделали. Но игра читает не `overrides.json`, а собранный
`data/tracks.json`, поэтому правки попадают в неё только после пересборки.
Её запускает кнопка **«Применить в игру»** в шапке редактора — она делает ровно
то же, что

```bash
npm run build:catalog
```

Сборка идёт по кэшу `.cache/`, поэтому занимает секунды и в сеть почти не
ходит. После неё обновите вкладку с игрой.

Точка старта из редактора всегда главнее автоматического детектора тишины:
человек слышал трек, а детектор только считал RMS.
